# New England Seamount (NESMA) — 2D BELLHOP Eigenray Transects

MATLAB scripts for running 2D eigenray models along straight-line transects across the New England Seamount area, using BELLHOP and Michael Porter's Acoustics Toolbox. For each transect, the scripts cut a bathymetry profile out of a high-resolution survey grid, write the BELLHOP input files, run the model and plot the eigenrays over the seafloor.

## Requirements

- MATLAB
- Acoustics Toolbox MATLAB functions in `acoustictoolkit/`: `bellhop`, `write_env`, `writebdry`, `plotray`, `plotbty`
- A compiled BELLHOP (2D) binary in `bellhop/`
- `NESMA_RR2409_bathy_25m.mat` Needs to be downloaded [link](https://drive.google.com/file/d/18E9dFyUA-nb3en8ZNd6JojhD327lIYtl/view?usp=drive_link)

Unlike the 3D test case, no `.env`, `.bty` or `.ssp` files need to be prepared in advance. Everything is generated by the scripts.

## Running

Open MATLAB, navigate into this folder, and run:

```matlab
NESMA_2dEigen
```

The script loads the bathymetry from the current folder, so run it from this folder. The bathymetry is kept in the workspace between runs (`clearvars -except lar lor zr`), so it only loads the first time.

Each case produces one figure and these files in `env/`:

| File                       | Contents                     |
|----------------------------|------------------------------|
| `NESMA_<case>.env`         | Environment file             |
| `NESMA_<case>.bty`         | Bathymetry profile           |
| `NESMA_<case>.ray`         | Eigenrays (BELLHOP output)   |
| `NESMA_<case>.prt`         | BELLHOP run log              |

## Folder layout

```
<root>/
├── setup_paths.m        Adds toolbox and binaries to the MATLAB path
├── NESMA_2dEigen.m      Main script: runs and plots all transect cases
├── make_transect.m      Samples range and depth along a source–receiver line
├── write_eig_env.m      Writes the BELLHOP .env file for an eigenray run
├── prep_envfiles.m      Copies shared .bty/.ssp files to match a case name (not used here)
├── NESMA_RR2409_bathy_25m.mat   Bathymetry grid (25 m)
├── env/                 Generated input files and model output
├── bellhop/             BELLHOP executables
└── acoustictoolkit/     Acoustics Toolbox MATLAB code (added recursively)
```

`setup_paths` creates `env/` if it is missing. The `bellhop/` and `acoustictoolkit/` folders must be supplied.

## Files

### `NESMA_2dEigen.m`

Defines the transect cases and loops over them. Source and receiver positions are given as `[lat lon]`:

| Case    | Source (lat, lon) | Receiver (lat, lon) |
|---------|-------------------|---------------------|
| `Case1` | 38.80, −64.30     | 38.80, −63.85       |
| `Case2` | 38.60, −63.80     | 38.60, −62.85       |
| `Case3` | 39.10, −64.90     | 39.10, −64.45       |

For each case it:

1. Builds the transect with `make_transect`.
2. Sets the maximum water depth `Dmax` from the deepest point on the transect.
3. Writes the bathymetry with `writebdry` (`'L'` = linear interpolation between points).
4. Writes the environment file with `write_eig_env`.
5. Runs BELLHOP.
6. Plots the rays with the bathymetry on top, titled with the case name and transect length.

To add a case, add another entry to each field of the `cases` struct.

### `make_transect.m`

```matlab
[rkm, zb, lat, lon, rR] = make_transect( src, rcv, lar, lor, depth );
```

Samples 500 evenly spaced points along a straight line from the source to the receiver, in latitude and longitude.

- The line runs **5% past the receiver** (`t` goes from 0 to 1.05) so the bathymetry extends beyond the rays' stopping range.
- `rkm` is the cumulative distance along the track in km, computed with the haversine formula (Earth radius 6371.0088 km).
- `zb` is the depth at each point, interpolated from the grid with `interp2`.
- `rR` is the range to the receiver itself (at `t = 1`), in km.

**Inputs:** `src` and `rcv` as `[lat lon]`; the bathymetry grid in the form `interp2(lor, lar, depth, …)` expects.

**Outputs:** `rkm` (km), `zb` (m), sampled `lat` and `lon`, and `rR` (km).

Points outside the bathymetry grid come back as `NaN`, so every transect must lie inside the grid's coverage.

### `write_eig_env.m`

```matlab
write_eig_env( name, Dmax, rR );
```

Writes `<name>.env` for a BELLHOP eigenray run at **1000 Hz**.

| Setting               | Value                                                       |
|-----------------------|-------------------------------------------------------------|
| Sound speed profile   | Canonical Munk profile, 50 m steps from 0 to `Dmax`         |
| Surface               | Vacuum, linear SSP interpolation, attenuation in dB/λ (`CVW`) |
| Bottom                | Acoustic halfspace, bathymetry read from `.bty` (`A*`)       |
| Bottom properties     | 1600 m/s, 1.8 g/cm³, 0.8 dB/λ, no shear                     |
| Source depth          | 1200 m                                                      |
| Receiver              | 1440 m depth, at range `rR`                                  |
| Beams                 | 5101 beams from −90° to 90°, automatic step size            |
| Ray box               | Depth `Dmax + 100` m, range `rR × 1.02` km                  |
| Run type              | `E` (eigenrays)                                             |

The Munk profile is a standard idealized deep-ocean profile, not measured sound speed data for this site. To use a measured profile, replace `z` and `c` at the top of the function.

### `setup_paths.m`

```matlab
paths = setup_paths();
```

Returns a struct of folder locations, all relative to where `setup_paths.m` lives:

| Field        | Folder              |
|--------------|---------------------|
| `paths.root` | This folder         |
| `paths.env`  | `env/`              |
| `paths.bin`  | `bellhop/`          |
| `paths.at`   | `acoustictoolkit/`  |

It also adds `acoustictoolkit/` (with all subfolders) and `bellhop/` to the MATLAB path.

### `prep_envfiles.m`

```matlab
fileroot = prep_envfiles( paths, caseName );
```

Copies `env/KoreanSea.bty` and `env/KoreanSea.ssp` to `env/<caseName>.bty` and `.ssp`, and returns `env/<caseName>`. It is not called by `NESMA_2dEigen.m`, which generates its own input files.

## Notes

- Source and receiver depths are the same for all cases. Change `Pos.s.z` and `Pos.r.z` in `write_eig_env.m` to adjust them, or add them as arguments to give each case its own depths.
- All three cases run along constant latitude (east–west transects).
